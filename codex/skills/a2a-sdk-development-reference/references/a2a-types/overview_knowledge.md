# Types: hierarchy, lifecycle, transport flows

Inspected a2a-sdk 1.1.4, 2026-10-07; installed source `.venv/lib/python3.11/site-packages/a2a/types`. Four non-cache files: package exports, generated protobuf implementation, static stubs, generated gRPC wiring. These models are mutable local wire objects, not Pydantic models, task stores, live agents or transport clients.

## Resource hierarchy

AgentCard describes agent name/version/provider, capabilities, interfaces and skills. Interface URL/binding/tenant/protocol_version describes routing; skill id identifies advertised operation, not a Python callable. Card.security_schemes maps names to SecurityScheme oneof; SecurityRequirement maps scheme name to scope lists. OAuth flow endpoint URLs describe authorization/token destinations. No credentials are acquired, refreshed or validated by model construction. Signatures are detached JWS values checked by utils.signing.

Task.id identifies task, Task.context_id groups context, Message.message_id identifies message; message task/context/reference IDs establish logical links. Task contains status, artifacts, history and metadata. TaskStatus has state/message/timestamp; Artifact contains Parts. Part.content oneof chooses text/raw/url/data; metadata/filename/media_type annotate. Status/artifact events refer to task/context and provide changes. Their construction never applies changes to Task: consuming handler owns lifecycle/append consistency. TaskState includes submitted, working, completed, failed, canceled, input_required, rejected, auth_required; enum allows values without enforcing transition rules.

TaskPushNotificationConfig is tenant/task/config-scoped callback configuration; callback URL/token/authentication.credentials are serializable values whose sensitive destination is push sender/callback, not public agent credential definitions. Models impose no expiry or persistence. Get/Delete requests carry task_id and config id separately; list requests carry cursor. Tenant is a routing string, not authenticated principal. task/context IDs and config IDs can collide across tenants unless storage/service scopes them; generated code gives no authorization or uniqueness guarantee.

## Requests and wire behavior

SendMessageRequest contains required Message and optional SendMessageConfiguration (accepted output modes, callback config, optional history_length, return_immediately). It is used by both SendMessage and SendStreamingMessage. Unary response chooses Task or Message in payload; stream envelope chooses Task, Message, status or artifact update. Empty payload is constructible and must be handled at integration boundary. Return-immediately flag describes remote behavior; no scheduler runs in model.

GetTaskRequest optional history_length distinguishes absent from zero; absent means no limit at utility level, zero means clear history. ListTasksRequest has context/status/timestamp filters, cursor, optional page_size/history/include_artifacts; filter application/defaulting/order/consistency belongs to remote handler. ListTaskPushNotificationConfigsRequest.page_size has no presence bit, unlike ListTasksRequest.page_size. CancelTaskRequest only represents intent; generated skeleton does not check cancelability or terminate computation. GetExtendedAgentCardRequest contains tenant only; gRPC metadata/context supplies authentication elsewhere.

Binary serializers use descriptor field numbers/types. JSON conversion uses camelcase names, base64 bytes, symbolic enums, RFC3339 timestamps and Struct/Value natural JSON. Google REQUIRED annotations are metadata; serialization does not automatically run utils validator. Message creation succeeds with missing required fields. Synthetic optional oneofs preserve explicit false/zero/empty string; ordinary proto3 scalars cannot distinguish absent from default. Oneof switching clears previous member. Complete field/options catalog includes deprecated OAuth implicit/password and synthetic map-entry descriptors.

## Transport execution

Import a2a_pb2 registers dependencies and constructs message classes, no network. Stub(channel) binds 11 channel callables with serializer/deserializer pairs and /lf.a2a.v1.A2AService/<Method> path. Invoking SendMessage serializes request → channel RPC → bytes parsed to SendMessageResponse; two unary-stream methods deserialize each StreamResponse item. grpc.aio channels supply awaitable/async stream behavior, sync channels supply sync behavior. Generated code itself has no async def, retry/backoff, reconnect, task cache or transaction boundary.

Server registration maps request bytes → request FromString → servicer method(request,context) → response SerializeToString. Base servicer sets UNIMPLEMENTED/details then raises NotImplementedError for every method. User subclass and service framework own auth, validation, cancellation, deadlines and state changes. Experimental static methods delegate to grpc.experimental with target/credentials/options/timeout/metadata; these can initiate network calls and were not executed. Credentials lifetime/destination are caller/gRPC responsibilities: channel credentials protect target connection; per-call credentials and metadata flow to target for individual requests. Sensitive protobuf fields can be serialized without redaction.

No local promise of event ordering/replay, snapshot pagination consistency, idempotent cancellation, or server resource deletion can be inferred from generated methods. Deadline/cancellation propagation uses gRPC runtime, not local recovery logic. Define client timeouts and authorize tenant/task/config access in actual service. grpc is absent in inspected environment: generated wiring inspected via AST/descriptor; fake channel tests validate all bindings without live RPC or installing extras.
