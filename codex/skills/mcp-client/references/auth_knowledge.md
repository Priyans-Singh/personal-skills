# `mcp.client.auth`: OAuth client authentication

Source inspected: MCP 1.30.0; covers `auth/__init__.py`, `exceptions.py`, `oauth2.py`, `utils.py`, empty `extensions/__init__.py`, and `extensions/client_credentials.py`. Public re-exports are `OAuthClientProvider`, `OAuthFlowError`, `OAuthTokenError`, `OAuthRegistrationError`, `PKCEParameters`, `TokenStorage`; machine credentials providers require `mcp.client.auth.extensions.client_credentials`.

## Interactive OAuth

Implement async `TokenStorage`: `get_tokens`, `set_tokens`, `get_client_info`, `set_client_info`. It persists bearer tokens/DCR credentials; there is no delete method, so failed refresh clears only in-memory context. `PKCEParameters.generate()` makes 128-char unreserved verifier and SHA-256 URL-safe no-padding challenge (both validate length 43–128).

`OAuthClientProvider(server_url, client_metadata, storage, redirect_handler=None, callback_handler=None, timeout=300, client_metadata_url=None)` is HTTPX `RedirectAwareAuth`. CIMD URL must be HTTPS with non-root path. It locks concurrent flows, loads storage lazily, adds Bearer for valid unexpired token (no expiry skew), otherwise tries refresh. It begins discovery only after 401 or 403 `insufficient_scope`: parses `WWW-Authenticate`, discovers protected-resource metadata, validates requested resource is its parent/equal, picks authorization server, discovers issuer-validated OAuth metadata, chooses scope (challenge > resource server > AS), then reuses compatible registration, CIMD, or DCR. Code flow needs first redirect URI, redirect handler, and callback `(code, state)`; it sends PKCE/state then constant-time validates returned state. Token response status must be 200 and is persisted; refresh failure logs/clears memory and falls through. Original request retries once with Bearer. There is no generic retry/backoff/revocation. Auth-internal redirects only follow same origin/default HTTP→HTTPS, max 5.

`OAuthContext` owns canonical resource selection, resource-parameter decision (PRM or protocol >=2025-06-18), token expiry, and `client_secret_basic`/`client_secret_post` form/header shaping. Utilities parse simple first-match auth fields, build well-known metadata candidates, parse/validate metadata, build DCR requests, and parse registrations/tokens. `OAuthFlowError` is base; token and registration subclasses distinguish failure class.

## Machine credentials

`ClientCredentialsOAuthProvider(server_url, storage, client_id, client_secret, token_endpoint_auth_method="client_secret_basic", scopes=None, issuer=None)` sends `grant_type=client_credentials`, optional resource/scopes, and Basic or form secret. Pass `issuer`: omitted currently warns and first discovered AS wins; configured issuer prevents secret transmission to mismatched metadata.

`PrivateKeyJWTOAuthProvider(server_url, storage, client_id, assertion_provider, scopes=None, issuer=None)` sends private-key JWT client assertion; provider receives AS issuer, not resource URL. `SignedJWTParameters(issuer, subject, signing_key, signing_algorithm="RS256", lifetime_seconds=300, additional_claims=None).create_assertion_provider()` signs fresh `iss/sub/aud/iat/exp/jti`; additional claims override duplicate generated claims. `static_assertion_provider(token)` ignores audience, safe only for a prebuilt suitable token. Deprecated `RFC7523OAuthClientProvider`/`JWTParameters` support legacy bearer-JWT grant/code-flow auth; do not start new use.
