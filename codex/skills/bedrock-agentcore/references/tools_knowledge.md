# AgentCore Tools — Browser, Code Interpreter, and Web Search

`bedrock_agentcore.tools` has two sandbox families—provisioned Browser and Code Interpreter resources plus short-lived sessions—and a Web Search client which invokes a Gateway MCP connector. Control-plane methods create/list/delete named resources; data-plane methods start/use/stop sessions. Keep those lifecycles separate.

## Configuration objects: `tools/config.py`

Every `to_dict()` converts friendly snake_case fields to the service's required wire shape; clients accept either these objects or raw compatible dictionaries. `VpcConfig(security_groups, subnets)` produces `securityGroups`/`subnets`. `NetworkConfiguration(network_mode='PUBLIC', vpc_config=None)` permits only `PUBLIC` or `VPC`; VPC requires `VpcConfig`. Use `NetworkConfiguration.public()` or `.vpc(groups, subnets)`.

Browser resource/session controls are composable: `S3Location(bucket, key_prefix)` and `RecordingConfiguration(enabled, s3_location)` serialize recordings; `.disabled()` and `.enabled_with_location()` are safe constructors. `BrowserSigningConfiguration(enabled)` controls Web Bot Auth, with `.enabled_config()`/`.disabled_config()`. `ViewportConfiguration(width,height)` has fixed `.desktop_hd()` 1920×1080, `.desktop_4k()` 3840×2160, `.laptop()` 1366×768, `.tablet()` 768×1024, and `.mobile()` 375×667.

For egress, `BasicAuth(secret_arn)` references a Secrets Manager JSON credential; `ProxyCredentials(basic_auth)` wraps it; `ExternalProxy(server, port, domain_patterns, credentials)` serializes as one `externalProxy`; `ProxyConfiguration(proxies, bypass_patterns)` supplies ordered proxies plus bypass domains. `ExtensionS3Location(bucket,prefix,version_id)` → `BrowserExtension(s3_location)` loads extensions. `ProfileConfiguration(profile_identifier)` persists browser state. `SessionConfiguration(name, viewport, proxy, extensions, profile)` is a convenience source for `BrowserClient.start(**config.to_dict())` (its dict intentionally uses that method's snake_case parameters).

`BrowserConfiguration(name, execution_role_arn, network_configuration, description, recording, browser_signing, tags)` and `CodeInterpreterConfiguration(name, execution_role_arn, network_configuration, description, tags)` generate control-plane API payloads. `EnterprisePolicyS3Location(bucket,prefix,version_id)` → `ResourceLocation(s3=...)` → `EnterprisePolicy(location,type)` points to a same-region JSON policy; its type is strictly `MANAGED` (creation) or `RECOMMENDED` (session start). `SecretsManagerLocation(secret_arn)` → `CertificateLocation(secrets_manager)` → `Certificate(location)` supplies a root CA; `Certificate.from_secret_arn()` builds that chain.

`create_browser_config(...)` is the common-options factory. It chooses public/VPC, requires groups + subnets for VPC, requires a recording bucket when recording is enabled, and conditionally adds signing. It returns—not creates—a `BrowserConfiguration`.

## Browser: `browser_client.py`

`BrowserClient(region, integration_source=None)` validates region, makes control and data boto3 clients with SDK User-Agent, and retains mutable `identifier` and `session_id` properties. A client represents at most one *current* session; pass explicit IDs to inspect others. `_to_dict` is the internal adapter behind all typed config inputs.

**Resource lifecycle.** `create_browser(name, execution_role_arn, network_configuration=None, description=None, recording=None, browser_signing=None, enterprise_policies=None, certificates=None, tags=None, client_token=None)` provisions a custom browser (public network default), converts policy/cert objects, and sends an idempotency token if supplied. Enterprise policies here must be `MANAGED`. `delete_browser(browser_id, client_token=None)`, `get_browser(browser_id)`, and `list_browsers(browser_type=None, max_results=10, next_token=None)` are direct control-plane wrappers; list supports `SYSTEM`/`CUSTOM` filtering and caller-driven pagination. Deletion is asynchronous service state, not proof that all sessions vanished.

**Session lifecycle.** `start(identifier='aws.browser.v1', name=None, session_timeout_seconds=3600, viewport=None, proxy_configuration=None, extensions=None, profile_configuration=None, enterprise_policies=None, certificates=None)` calls `start_browser_session`, saves returned browser/session IDs, and returns the session ID. Session timeout range is service-limited (documented 1–28,800 seconds). These policies are `RECOMMENDED`. `stop()` is idempotent locally: no current IDs returns `True`; otherwise it calls stop and clears both IDs only after success. `get_session(browser_id=None, session_id=None)` and `list_sessions(browser_id=None, status=None, max_results=10, next_token=None)` use current IDs when omitted and raise `ValueError` if unavailable. `update_stream(stream_status, ...)` sends `ENABLED`/`DISABLED` for automation stream control.

**Automation handoff.** `generate_ws_headers()` starts a default session if absent, SigV4-signs the automation WebSocket GET with current AWS credentials, and returns `(wss_url, headers)`; missing credentials is `RuntimeError`. `generate_live_view_url(expires=300)` similarly starts if needed and generates a query-signed live-view URL; expiry over 300 seconds is rejected. `take_control()` ensures a session then disables automation; `release_control()` re-enables it, but only warns/no-ops without a session. `browser_session(...)` is the exception-safe context manager: create client → start with supplied session options → yield → always `stop()`.

## Code Interpreter: `code_interpreter_client.py`

`CodeInterpreter(region, session=None, integration_source=None)` has the same current `identifier`/`session_id` model; its optional boto3 Session controls credential resolution. `create_code_interpreter(name, execution_role_arn, network_configuration=None, description=None, certificates=None, tags=None, client_token=None)`, `delete_code_interpreter(interpreter_id, client_token=None)`, `get_code_interpreter(interpreter_id)`, and `list_code_interpreters(interpreter_type=None, max_results=10, next_token=None)` mirror Browser provisioning. `start(identifier='aws.codeinterpreter.v1', name=None, session_timeout_seconds=900)`, `stop()`, `get_session(...)`, and `list_sessions(...)` mirror the Browser session operations, with a 15-minute default.

`invoke(method, params=None)` is the primitive data-plane call. It auto-starts when necessary and forwards `name=method`, `arguments=params or {}`. The conveniences build on it:

- `upload_file(path, content, description='')` rejects absolute paths, maps `str` to `text` and `bytes` to `blob`, invokes atomic `writeFiles`, and records non-service local description metadata. `upload_files(files)` applies the same relative-path rule and writes all supplied files in one `writeFiles` call; its all-or-nothing behavior is service-side.
- `install_packages(packages, upgrade=False)` rejects an empty list and package strings failing the SDK allowlist, shell-quotes each accepted name, then invokes `executeCommand` with pip. This validates package *syntax*, not package safety or availability.
- `download_file(path)` invokes `readFiles`, walks streamed resource blocks, returns text where possible else bytes, and raises `FileNotFoundError` if it cannot find usable content. `download_files(paths)` returns the successfully decoded `file://` resources keyed by paths; unlike singular read, missing entries simply do not appear.
- `execute_code(code, language='python', clear_context=False)` accepts only Python, JavaScript, TypeScript and calls `executeCode`. Python variables/imports persist across calls unless cleared; clear context is ignored by non-Python service contexts. `execute_command(command)` forwards a shell command—sandbox isolation does not make untrusted commands safe. `clear_context()` invokes Python `executeCode` with `clearContext=True`.

`code_session(region, session=None, identifier=None)` starts, yields, and finally stops an interpreter, including when the body raises.

## Web Search: `web_search_client.py`

`WebSearchClient` is not a general web scraper. It calls fixed MCP tool `WebSearch` via an AgentCore Gateway target, signs requests with ordinary AWS credentials, and normalizes the connector's JSON text result. The caller needs `bedrock-agentcore:InvokeGateway`; the gateway role needs `bedrock-agentcore:InvokeWebSearch`.

Construct `WebSearchClient(region=None, gateway_id=None, gateway_arn=None, gateway_endpoint=None, target_name=None, tool_name=None, backend=None, boto3_session=None, timeout=30, integration_source=None)`. Exactly one routing source is required: ID, ARN, endpoint, or injected `WebSearchBackend`. ARN derives its ID/region; endpoint is AWS-host validated; supplying target/tool names avoids discovery rounds. `KNOWN_REGIONS` only warns outside its list. A supplied backend bypasses gateway construction. Use it as a context manager or call `close()`; only clients that created their backend close it.

`search(query, max_results=None, include_domains=None, exclude_domains=None, published_after=None, published_before=None)` validates nonblank ≤200-char query, result count 1–25, each domain list ≤100, builds connector filters, invokes backend, then returns `WebSearchResponse`. Filter support requires connector >=1.2.0. Request filters can only narrow target configuration: exclusions win; includes intersect, so conflicting include rules yield a valid empty result.

`WebSearchResult(text, url=None, title=None, published_date=None).from_payload()` maps one result (`publishedDate` to snake case). `WebSearchResponse(results=[], search_id=None).from_payload()` maps a response; it supports `len()` and iteration. `WebSearchError` means MCP/tool/JSON protocol failure. `WebSearchBackend.search()` is the pluggable transport contract and `.close()` cleanup hook; base search raises `NotImplementedError`. `GatewayMcpBackend(endpoint, region, ...)` implements a narrow SigV4 streamable-HTTP MCP lifecycle (initialize, notification, optional tool discovery, tools/call) and accepts JSON or SSE responses. Its `search(arguments)` decodes the tool payload; `.close()` releases its HTTP pool.

Internal protocol helpers are intentionally not application API: `_build_arguments` and `_checked_domains` enforce limits; `_extract_search_payload`/`_first_text` convert MCP content or raise `WebSearchError`; `_decode_jsonrpc`, `_answers`, `_iter_sse_messages` handle JSON/SSE framing; `_parse_gateway_arn` validates and extracts gateway ID/region. They explain failures but should not be depended upon.

Inside `GatewayMcpBackend`, `_next_id` allocates JSON-RPC request IDs; `_signed_headers` performs SigV4 header construction; `_post` sends one signed MCP request and selects JSON/SSE decoding; `_reset_session` discards protocol state after a transport/protocol failure; `_ensure_initialized` performs the MCP handshake once; `_ensure_tool_name` and `_list_tool_names` discover the target-prefixed tool name when it was not supplied. The nested SSE `flush` helper assembles one event's data lines before JSON decoding. These are implementation details, but together explain why one `search()` can make handshake/discovery calls before the tool call.
